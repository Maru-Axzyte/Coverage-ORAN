Or run `python zamani_grid_milp/main.py` from the project root. This runs only the new baseline. It reuses historical WE results on 20 uniformly sampled 70-UE maps, selected without using method outcomes. Map selection is frozen with seed 20261016. Every original UE coordinate and demand is preserved.

## What is implemented

Inspired by Section 3.2 of Zamani et al., *Optimization of unmanned aerial vehicle augmented ultra-dense networks* (2020), DOI https://doi.org/10.1186/s13638-020-01804-3.

The core retained mechanism is quantization of placement and joint MILP selection of positions, user associations and resources. This is the MILP branch, not the paper's PSO branch or a full reproduction of both branches.

The environment is adapted to this project's fixed UAV count, orthogonal global PRB pool, existing propagation/antenna model, discrete link power/PRB modes and minimum 3D UAV separation. The paper's RRHs, fronthaul and hover/circuit-power costs are absent. Objective order matches the shared fixed-placement allocation oracle: maximize served UE count, maximize admitted demand, minimize PRBs, minimize transmit power. It does not import WE's evolving contextual resource preference.

For identical UAVs, one binary `y_s` indicates selection of candidate `(x,y,h,theta)`. Link-mode binaries `z_skm` choose a QoS-feasible PRB/power combination. Constraints are:

- `sum_s y_s = number_of_UAVs`, including idle selected UAVs.
- Each UE is served at most once.
- `sum_m z_skm <= y_s`.
- Per selected site, link power sum <= UAV power limit, PRB sum <= its configured upper bound.
- Global link PRB sum <= 135 (from the saved environment).
- Physically incompatible candidate pairs cannot both be selected; all selected UAVs, including idle ones, obey separation.

Geometry conflicts are compressed by horizontal grid groups only when this is exactly equivalent to all pairwise 3D conflicts. Radio modes are generated by the existing `UAVMILP.precompute_service_modes()` for one representative UAV, avoiding identical UAV-label copies. Saved watt power levels are restored without activating the optional legacy dBm grid. The incumbent is independently checked against `env.py` rates, power, PRBs, single association and separation.

## Resolution and time budget

Defaults follow the existing `config.grid_size=10`: 11 x 11 horizontal coordinates, all 6 saved heights and all 7 saved antenna angles, giving 5082 candidates. No historical WE placements are injected into the candidate set. WE searches continuous positions; solver optimality/gaps apply only to this finite candidate set.

By default, each map receives a total wall-time budget equal to that map's recorded WE elapsed time. Preprocessing and model-building time are subtracted before calling HiGHS. If they consume the budget, the solver receives zero time and may have no incumbent. These phases cannot be interrupted exactly at the deadline, so total time and possible overrun are recorded. Historical WE times may be from different hardware; this is an exploratory budget policy, not a controlled speed comparison.

Use a fixed total budget if desired:

```powershell
python main.py --time-limit 1800 --output-dir results_1800s
```

Check multiple resolutions with separate output folders, for example `--grid-intervals 5 --output-dir results_grid5`. A coarse grid alone is not evidence that continuous WE is superior. HiGHS requested MIP gap is zero, but it may stop at the time limit with a feasible non-optimal incumbent. The logged MIP gap belongs to the combined lexicographic objective, not a percentage error in served count. A separate conservative served-count upper bound is reported for the grid.

## Outputs and resuming

- `results/selection.json`: frozen 20-map plan, settings and fingerprints.
- `results/inputs`: exact source maps and WE results.
- `results/logs/ue_070_map_XXX.log`: live per-map console transcript.
- `results/logs/ue_070_map_XXX.highs.log`: native solver progress.
- `results/runs`: per-map incumbent, per-UAV power/PRBs, rates, placement, solver status, bounds, gap, node count, model size and timings.
- `results/comparison.csv`, `comparison.json`, `comparison.png`: paired summaries updated after each completed map.

Power/PRB comparisons are marked comparable only when both solutions are feasible and served count plus admitted demand match. Whether the actual served UE set matches is also recorded. Missing integer incumbents are explicitly flagged; the service summary counts them as zero. A map that reaches its time budget is a completed experiment even if not optimal.

Run the same command after interruption: completed maps are skipped; an unfinished map restarts. Only one process can own the output directory. Changed code/settings/input data require a new output directory, preserving older results.

`--prepare-only` freezes and validates inputs without optimization. `--plot-only` rebuilds summaries from existing completed results. Tests: `python -B test_model.py` from this directory; these use tiny synthetic models, not the 20 benchmark maps.
